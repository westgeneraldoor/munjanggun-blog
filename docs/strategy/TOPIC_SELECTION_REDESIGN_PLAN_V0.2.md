# 소재 선정 구조 개편 기획 v0.2

> 작성일: 2026-08-06
> 상태: 데이터 복구·블라인드 분류 1차 완료, 2026-08-15 재집계 대기
> 결론 제한: 이 문서는 `axis_type`, 카니발 예외, 발행 배분 비율을 아직 운영 규칙으로 확정하지 않는다.

## 한눈에 보는 결론

지금 확정할 수 있는 것은 세 가지다.

1. 과거 성과 원장은 TOP20 헤딩과 제목 표기 흔들림 때문에 크게 누락돼 있었다.
2. 누락을 복구한 뒤에도 현재 Codex와 Claude는 이미 성패를 봤기 때문에 소재 유형 분류자가 될 수 없다.
3. 새 분류자 2명과 중재자 1명의 블라인드 분류에서는 사전 정의한 소재 3축의 안정적인 주효과를 확인하지 못했다. 이것은 소재가 성과와 무관하다는 확정이 아니다.

따라서 순서는 아래로 고정한다.

```text
데이터 복구
→ 성패를 가린 익명 자료 생성
→ 결과를 본 적 없는 새 분류자 2명이 독립 분류 완료
→ 불일치 항목 중재와 합의 라벨 해시 고정 완료
→ 같은 발행 구간 안에서만 성패 비교
→ 2026-08-15에 작성되는 2026년 8월 14일 기준 daily 관측 완료
→ 2026-08-15 재집계
→ 그때 운영 규칙 개정안을 별도 승인
```

## 1. 이번에 확인·수정한 데이터 기반

- 2026-08-06 daily report와 TOP20 20행

- 폐기된 087·172 상태 유지

### 1-2. TOP20 헤딩 6종을 모두 인식

기존 파서는 `## 게시글 TOP20`만 읽었다. 번호가 붙거나 `TOP 20`처럼 띄어 쓴 헤딩도 읽도록 수정했다.

현재 실제 리포트에서 확인된 형식은 6종이다.

- `## 게시글 TOP20`
- `## 4. 게시글 TOP20`
- `## 4. 게시글 TOP 20`
- `## 3. 게시글 TOP 20`
- `## 3. 게시글 TOP 20 관찰`
- `## 5. 게시글 TOP20`

최신 2026-08-06 파일까지 전수 검산한 결과:

| 항목 | 결과 |
| --- | ---: |
| daily 파일 | 56일 |

| TOP20 순위 행 | 1,020행 |
| 매핑된 관측 행 | 1,003행 |

### 1-3. daily 원본은 고치지 않고 등록부에 별칭을 둠

`POSTING_REGISTRY.json` 최상위에 `title_aliases`를 추가했다. 유사도 자동 매칭은 사용하지 않는다.

매칭 순서는 아래다.

1. daily의 명시적 글번호
2. 등록부 정본 제목 정확 일치
3. 등록부의 확인된 별칭 정확 일치
4. 어느 것도 아니면 `unmapped_titles`

같은 별칭이 두 글에 연결되면 한쪽을 추측하지 않고 미매칭으로 남긴다.

기존 수집기 코드에 박혀 있던 086번 제목 이력도 `title_aliases`로 옮겼다.

| 단계 | 미매칭 제목 | 미매칭 행 |

| 새 헤딩 파서, 별칭 이전 전 | 22 | 85 |
| 확인 별칭 적용 후 | 9 | 17 |
| 회수 | 13 | 68 |

남은 9개는 등록 글번호를 확정할 직접 근거가 부족해 보존했다.

- 베이지 중문 과거 제목 2종: 2행

## 3. 블라인드 분류 설계

### 3-1. 분류자 자격

분류자는 `post_performance.json`의 verdict, 과거 landed/faded 목록, 이 기획서 v0.1의 결론을 본 적 없는 새 세션이어야 한다.

- 현재 Claude: 제외
- 현재 Codex: 제외
- 새 분류자 A: 123건 분류 완료
- 새 분류자 B: 123건 분류 완료
- 새 판정자 C: 불일치 49개 축 판정 완료
- 합의 라벨 SHA-256: `1b28c307fff36cd240020cbbaa15bfe10c387e42f299c0f3674bed50bf19b824`

### 3-2. 분류 자료

`npm run topic:blind:prepare`가 아래 파일을 만든다.

`outputs/reports/topic_analysis/2026-08-06_topic_blind_dataset.json`

123개 초기 판정 완료 글을 담되 각 행에는 아래 다섯 필드만 있다.

- `blind_id`
- `title`
- `target_keywords`
- `topic_summary`
- `has_summary`

글번호, 파일명, URL, 발행일, 발행순서, queue_id, verdict, 관측일, 순위, 조회수는 넣지 않는다.

제목·키워드·요약의 날짜 표기는 `[날짜 마스킹]`으로 바꾼다. 결과·운영 방식을 암시하는 문장은 문장 단위로 제거하고, 등록부의 실제 글번호나 `NNN_이름.md` 형태의 파일명이 다른 게시글을 가리키는 문맥에서는 `[다른 글]`로 바꾼다. 생성기는 정제 후 금지 패턴과 깨진 마스킹 토큰을 다시 검사하며 누출이 하나라도 있으면 파일을 쓰지 않는다. `has_summary`는 키워드나 정제된 요약 중 하나라도 있으면 `true`이며, 제목만 있는 27건을 분석에서 분리하기 위한 값이다. 운영 메모를 제거한 자리에 새 요약을 작성해 채우거나 요약 길이를 맞추기 위해 소재 설명을 절단하지 않는다. 70자 일괄 절단은 요약이 있는 96건 중 62건의 분류 근거를 줄이면서도 제목·키워드의 시기 지문을 없애지 못하므로 적용하지 않는다.

익명 ID는 SHA-256 앞 12자리를 숫자가 없는 `a~p` 문자 코드로 표현한다. 동일 글은 재실행할 때 같은 ID가 나오므로 언블라인딩은 가능하지만, 저장소에 접근하면 글번호 후보를 대입해 역산할 수 있다. 따라서 분류자에게는 저장소가 아니라 `C:\Users\hjh\블라인드분류`의 데이터셋과 라벨 정의 두 파일만 전달한다.

### 3-3. 먼저 분류할 특징

`new_axis`/`derivative`는 과거 순서와 기존 글 관계를 알아야 하므로 첫 블라인드 분류의 정답처럼 사용하지 않는다. 먼저 제목과 소재만 보고 판정 가능한 특징을 분류한다.

| 필드 | 허용 값 |
| --- | --- |
| `intent_type` | cost / symptom_repair / comparison / installation_constraint / design_case / brand_service / other |
| `demand_breadth` | broad / mid / narrow |
| `problem_explicitness` | explicit / implicit / none |
| `service_alignment` | direct / adjacent / unclear |
| `confidence` | high / medium / low |

분류자는 성과를 예상하거나 `잘될 글`, `실패할 글`을 적지 않는다.

### 3-4. 독립성 검사

두 분류 결과를 합치기 전에 아래를 검사한다.

- 두 파일 모두 모든 `blind_id`를 정확히 한 번 포함
- 추가 ID와 누락 ID가 없음
- 허용 값 밖의 라벨이 없음
- 분류자가 결과 데이터를 보지 않았다는 선언이 있음
- 일치율과 Cohen's kappa를 필드별 기록

일치하지 않은 항목을 현재 Claude나 Codex가 임의로 정리하지 않는다.

## 4. 포화를 통제하는 비교 방법

전체 기간의 성공률을 앞뒤로 단순 비교하지 않는다. 같은 시기에 발행된 글끼리 비교한다.

| 구간 | 용도 |
| --- | --- |
| 2026-06-01~06-15 | 동일 시점 내부 비교 A |
| 2026-06-16~06-30 | 동일 시점 내부 비교 B |
| 2026-07-01~07-10 | 동일 시점 내부 비교 C |
| 2026-07-11~07-18 | 동일 시점 내부 비교 D |
| 2026-07-19~07-31 | 8월 15일까지 잠정, 8월 15일 재계산 E |

2026-08-06 성과 원장 기준의 단순 현황은 아래와 같다. 소재 특징과 결합하기 전 수치이며 원인 해석에는 쓰지 않는다.

| 구간 | 판정 글 | landed | faded | 달력상 D14 경과 | 달력상 D14 미경과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | 18 | 14 | 4 | 18 | 0 |
| B | 50 | 16 | 34 | 50 | 0 |
| C | 28 | 7 | 21 | 28 | 0 |
| D | 13 | 1 | 12 | 13 | 0 |
| E | 13 | 0 | 13 | 4 | 9 |

따라서 E 구간의 `0/13`은 현재 원장 출력일 뿐 최종 성공률이 아니다. 남은 9개가 달력상 D14를 지나고 관측 커버리지를 확인하기 전까지 잠정값으로만 쓴다.

각 구간 안에서 라벨별로 아래를 낸다.

- eligible 글 수
- landed 수와 비율
- faded 수와 비율
- 반대 라벨 대비 성공률 차이
- 표본이 작으면 신뢰구간과 Fisher exact test

한 구간에서 우연히 나온 차이를 전체 규칙으로 승격하지 않는다. 최소 3개 비교 가능 구간에서 방향이 반복되는지 본다. 7월 19~31일 구간은 2026년 8월 14일 데이터 기준일의 daily가 작성되는 2026-08-15 전에는 `0/13 확정`이라고 쓰지 않는다.

이 설계는 시점별 포화 수준 차이를 줄이지만, 네이버 알고리즘·경쟁 콘텐츠·제목 품질 같은 외부 요인을 모두 제거하지는 못한다. 결과는 인과 확정이 아니라 운영 실험 후보를 고르는 근거다.

블라인드 입력에서도 제목의 `3가지`·물음표 사용, 제목 길이, `target_keywords` 기록 개수처럼 콘텐츠 자체 또는 분류 근거인 시기 지문은 제거하지 않는다. 따라서 블라인드는 운영 메타데이터와 성과 직접 단서를 차단할 뿐 발행 시기를 완벽히 숨기지는 못한다. 소재 라벨과 성과의 관계가 실제로는 시기별 작성 방식 차이에서 나온 교란일 수 있으므로, 언블라인딩 후에는 반드시 위 발행 구간 내부에서만 비교하고 전체 기간 상관을 원인으로 해석하지 않는다.

## 5. 블라인드 소재 분류 1차 결과 (2026-08-06)

분류자 2명과 중재자 1명이 123건을 5개 축으로 라벨링했다. 라벨 신뢰도는 `intent_type`
kappa 0.937, `service_alignment` 0.885, `problem_explicitness` 0.743,
`demand_breadth` 0.627로 사전 기준 0.6을 통과했다. `confidence`는 0.470으로 기준 미달이라
필터로 사용하지 않는다. `service_alignment`는 96%가 `direct`로 분산이 없어 독립변수에서
제외했다.

D14가 완주한 W1~W4 109건을 발행 구간 안에서 비교한 결과, **사전 정의한 3개 축에서
안정적인 주효과를 확인하지 못했다.** 발행 구간 내 순열검정 p값은 `demand_breadth` 0.083,
`problem_explicitness` 0.089, `intent_type` 0.183이었다. `broad` 대 `mid` 오즈비는
3.04(95% CI 0.89~10.42)로 방향은 있으나 1을 포함한다.

**소재가 성과와 무관하다고 확정한 것은 아니다.** 표본이 부족하고, 최초 문제의식이었던
큐 대표 키워드와 실제 글의 검색 의도 정합성, 실제 검색 수요 구간, 발행 당시 근접 글 누적
개수, 기존 허브와의 중복 강도는 이번 분류에서 측정하지 않았다. 정확한 표현은
**제목·요약에서 판정한 소재 폭만으로는 성과 차이를 안정적으로 설명하지 못했다**이다.

- 폐기된 가설: `새 축이면 성공한다` — 결과를 본 뒤 축을 붙인 순환논리였다.
- 지지되지 않은 가설: `narrow라서 실패했다` — W2+W3에서 narrow 45%, 구간 기저 29%였다.
- 미확인 가설: `broad면 회복된다` — 현재 신뢰구간으로는 우위와 무효를 모두 확정할 수 없다.

175번이 날짜 보정으로 `pending`이 되면서 123개 합의 라벨 중 현재 성과 분석 대상은 122개다.
합의 라벨과 데이터셋은 이력 보존을 위해 재생성하지 않고, 분석 결합 단계에서 175번을 제외한다.

## 6. 시간축 (2026-08-06 시점, 탐색적)

W1~W4에서 발행일이 1주 늦어질 때 landed 오즈는 약 0.47배였다. 날짜별 발행 묶음을
같은 군집으로 보정한 95% CI는 0.32~0.70이었다. 겹치는 D3~D14 경쟁 글이 10건 증가할 때
오즈는 약 0.57배였다(95% CI 0.38~0.85). 둘 다 관찰자료의 연관이며 인과 효과가 아니다.

**단일 분기점은 특정할 수 없다.** D14 완주 109건의 절단일을 전 구간에서 탐색하면

## 8. 사전 등록 검정 (2026-08-15 재집계용)

현재 남은 질문은 7/19 이후 발행분이 이전의 낮은 성공률 영역에서 추가로 벗어났는지다.
현재 W5 13건 중 달력상 D14 완주는 4건(161~164)이므로 답할 수 없다. 데이터 기준일 2026년 8월 14일의 daily를 2026-08-15에 확보하고 커버리지 가드를 통과한 뒤 아래 운영 판정 기준을 적용한다.

**판정 방법 (2026-08-10 추가).** `verdict` 필드를 그대로 세면 안 된다.
`verdictForPost`는 `observedDays >= 5`이면 D14가 지나기 전에도 `faded`를 찍는다.
2026-08-10 기준 13건 전부 `faded`로 표시돼 있으나, 그중 4건(176·177·178·179)은
D14 창이 닫히지 않았고 `landed` 조건(D3~D14 구간 TOP20 **2회** 이상)을 아직
산술적으로 충족할 수 있다.

따라서 판정은 각 글의 **D3~D14 창 안 실제 TOP20 등장 횟수**로 한다.
창이 닫혔는지(`발행일 + 14일 <= 데이터 기준일`)를 먼저 확인하고, 닫힌 글만 분모에 넣는다.

2026-08-10 기준 진행: 창 마감 8건(161~168) 전부 0회. 169는 남은 1일에 2회가 불가능해
사실상 확정. **9/13 확정, 4건 미결.**

| 08-15 결과 | 운영 해석 |
| --- | --- |
| 13건 전부 landed 조건 미충족 | 고정 기저 20% 가정에서 `0.8^13 ≈ 0.055`. 통상 5% 유의수준의 확정은 아니지만 추가 원인 조사를 재개하는 사전 신호로 사용한다. |
| 1건 이상 D3~D14 TOP20 2회 이상 | 20% 기저와 구별할 근거가 부족하다. `최근 붕괴` 서술을 철회한다. |
| 커버리지 미충족 글 존재 | `faded`로 강제하지 않고 판정을 보류한다. 13건 완전 판정 전에는 위 두 행을 적용하지 않는다. |

20%는 과거 기저의 추정치이며 불확실성이 있다. 이 표는 통계적 인과 확정 규칙이 아니라
결과를 본 뒤 기준을 바꾸지 않기 위한 운영상 사전 등록이다.

**모수 정의 (2026-08-07 확정).** 사전 등록한 모수는 2026-07-19~07-31에 발행된
**원고 글번호 13건**(161·162·163·164·165·166·167·168·169·176·177·178·179)이다.
이후 등록부에 추가된 리뷰릴스·legacy 행은 같은 날짜 구간에 들어오더라도
**분모에서 제외한다.** 원고 발행분의 검색 성과를 보는 검정이기 때문이다.
이 정의는 2026-08-07에 결과를 보기 전에 확정했으며 08-15 재집계 때 변경하지 않는다.

2026-08-10 기준 진행률: 창 마감 8건(161~168)은 모두 D3~D14 TOP20 0회다. 169는 남은 1일에 2회가 불가능해 사실상 확정이며, 176~179 4건은 2026-08-15 재집계 때 판정한다.
