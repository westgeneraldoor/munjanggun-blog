# 브릿지 코호트 사전 등록 (2026-08-24)

> **201~207 후보를 고르기 전에 판정법을 고정한 문서다.**
> 이번 7편은 브릿지 전략을 확정하는 검증군이 아니라, 다음 확장 여부를 정하는 **탐색 코호트**다.
> 후보나 결과를 본 뒤 모수·landed 정의·판정 구간을 바꾸지 않는다.

## 1. 검정할 것과 검정하지 않을 것

브릿지 글은 제품 키워드에서 시작하지 않는다. 생활·공정·가구·주거의 부모 검색 의도에서 출발해, 고객이 실제로 문·중문 때문에 결정해야 하는 지점으로 연결한다.

```text
부모 검색 의도
→ 부모 영역에서 고객이 하려는 일
→ 문·중문 때문에 생기는 실제 결정
→ 문장군이 취급하는 서비스
```

이번 코호트가 묻는 질문은 하나다.

> 같은 시기의 일반 발행글과 비교해, 구조화된 브릿지 7편에서 TOP20 진입 신호가 더 자주 나타나는가?

무작위 배정이나 동시 대조군이 없으므로 다음은 이번 코호트만으로 확정하지 않는다.

- 브릿지가 성과의 원인이라는 인과
- 부모 키워드 검색량이 브릿지 글로 그대로 이전된다는 주장
- 특정 서비스군의 재고 포화가 성과 하락의 원인이라는 주장
- 브릿지 전략 전체의 영구 채택 또는 영구 폐기

| 항목 | 고정값 |
| --- | --- |
| 모수 | 원고 글번호 **201~207, 7건** |

| 최종 판정일 | **207번 발행일 + 14일** |

| 분모 축소 금지 | 결과가 나쁜 글, 미발행 글, 수정 글을 사후에 빼서 7보다 작은 분모로 판정하지 않는다 |

일곱 후보는 원고 작성 전에 한 번에 승인받는다. 승인표에는 각 글의 `parent_keyword`, `service_keyword`, `service_family`, `relation_type`, `customer_question`, `dependency_statement`, 예정 제목, 예정 발행일을 적는다.

2026-08-24 사장님 최종 승인 결과는 `docs/strategy/BRIDGE_COHORT_APPROVAL_20260824.md`에 고정했다.

첫 원고를 쓰기 전에 다음 조건도 함께 고정한다.

- 부모 검색 의도는 7건 모두 서로 다르게 한다.
- 서비스군은 최소 3개를 포함하고, 한 서비스군은 최대 2건까지만 허용한다.
- 같은 서비스군을 연속 발행하지 않는다.
- 정확한 서비스 배분과 발행일은 승인표에서 고정한다. 성과를 본 뒤 교체하지 않는다.
- 일곱 후보가 모두 검증·승인되기 전에는 코호트 발행을 시작하지 않는다.

첫 발행 뒤 안전·사실 오류로 후보를 중단해야 하면 다른 글로 몰래 대체하지 않는다. 해당 사유를 기록하고 7건 전체 판정을 보류하거나 새 코호트로 다시 등록한다.

## 3. 브릿지 처치의 일관성

일곱 글은 아래 조건을 모두 충족해야 같은 처치로 센다.

1. 제목에서 부모 상황과 문·중문 결정이 둘 다 식별된다.
2. 첫 5문단 안에서 부모 상황이 왜 문 서비스 결정으로 이어지는지 설명한다.
3. 부모 업종 일반론이 아니라 문·중문 의사결정이 글의 주인공이다.
4. `npm run topic:bridge-check`에 다섯 인자를 모두 넣고 BLOCK 없이 통과한다.
5. 근접 글의 제목만 보지 않고 본문을 직접 읽어 같은 고객 질문이 아님을 확인한다.
6. 부모 검색량 전체를 이 글의 예상 유입량으로 간주하지 않는다.
7. 문장군이 부모 업종의 시공을 제공하는 것처럼 쓰지 않는다.

116·136·153·165는 사후에 브릿지와 비슷하다고 분류한 과거 글일 뿐, 사전 등록된 동일 처치군이 아니다. 네 글의 D3~D14 등장은 각각 1·1·0·0회이고 모두 faded지만, 주변 시기 성과를 고려한 전부 실패 확률이 약 50%라 브릿지 실패의 근거로 사용하지 않는다. 같은 고객 질문을 반복하지 않기 위한 보호글로만 쓴다.

## 4. 1차 성과지표와 커버리지

- 수집기의 `verdict` 필드를 읽지 않는다.
- 각 글의 `observation.day`가 **3~14**인 TOP20 등장만 직접 센다.
- **landed = D3~D14 TOP20 등장 2회 이상**이다.
- 발행일은 D0으로 계산한다.
- 관측 유효일은 D3~D14 중 TOP20 10행 이상이 확보된 날이다.
- 글 하나라도 관측 유효일이 3일 미만이면 분모에서 빼지 않고 7건 전체 판정을 보류한다. 누락 daily를 백필한 뒤 다시 계산한다.

이 3일 규칙은 리라이팅 코호트와 같은 사전 등록 규칙이다. 수집기 코드의 `observedDays >= 5` 분기와 동일하다고 표현하지 않는다.

검색 순위 추적값, 최고 순위, 최초 진입일, 총 등장 횟수, TOP20 중앙 나이, 부모 키워드 검색량은 원인 탐색용 보조지표다. 이 값으로 landed 판정을 뒤집지 않는다.

## 6. 사전 등록 판정 (7건)

| landed | 판정 | 미리 정한 행동 |
| ---: | --- | --- |
| **3건 이상** | **강한 확장 신호** | 다음 브릿지 코호트를 설계한다. 현 9.1%가 참이면 3건 이상 확률은 약 **2.0%**다. 다만 인과 확정이나 전면 전환으로 표현하지 않는다. |
| **2건** | **유망하지만 미확정** | 같은 규칙의 다음 7건으로 반복 확인한다. 현 9.1%가 참이면 2건 이상 확률은 약 **12.8%**라 한 번만으로 두 번째 엔진을 선언하지 않는다. |
| **1건** | **보류** | 현 시기 기준과 구분하기 어렵다. 서비스·관계·부모 의도별 기록만 남기고 다음 코호트 설계를 다시 검토한다. |

따라서 초안의 `2건 이상 = 브릿지 유효·즉시 채택`, `0건 = 브릿지 무효·제품 레인 복귀` 문구는 사용하지 않는다. 7건은 확정 표본이 아니라 탐색 표본이다.
