# daily 관측·실행 기록 계약 v2

> 목적: 성과 원장이 판정할 수 있는 형태로 daily를 남긴다. 지금 원장 175편 중 160편이 `unobserved`인 이유는 글이 안 먹혀서가 아니라 관측 기록이 없어서다.
> 적용: 2026-07-28 이후 작성하는 daily. 그 이전 파일은 소급 적용하지 않는다.
> 최종 업데이트: 2026-07-27

## 1. 왜 만드는가

2026-07-27 성과 원장 백필 결과다.

```
175편  landed 6 / faded 9 / unobserved 160
```

`unobserved` 160편은 실패가 아니라 **판정 불가**다. 원인은 세 가지였다.

| 원인 | 실태 |
| --- | --- |
| TOP20 표 누락 | daily 46일 중 10일이 행 5개 미만이거나 표 자체가 없음 |
| 발행일 부재 | 163번 이후 11편은 등록부 어디에도 발행일이 없음 |
| 제목 매핑 의존 | 표에 글번호가 없어 제목 문자열로 매칭해야 함. 제목이 바뀌면 유실 |

그리고 네 번째가 있다. **사람이 한 실행이 기록되지 않는다.** 2026-07-27 기준으로 내부 링크 보강 작업이 매일 진행되고 있었으나 daily 어디에도 남지 않았다. 그래서 조회수 변화가 검색 때문인지 링크 때문인지 구분할 수 없고, `정확 유입 미확인 → 확장 닫음` 판정 7건이 오염된 전제 위에 있었다.

## 2. TOP20 표 형식 고정

과거 daily는 헤더가 일곱 가지로 갈렸다. 아래로 고정한다.

```md
## 게시글 TOP20

| 순위 | 글번호 | 게시글 | 조회수 | 작성일 | 판단 |
| ---: | --- | --- | ---: | --- | --- |
| 1 | 140 | 드레스룸 슬라이딩도어가 불편한 집은 이유가 있습니다 | 56 | 7/8 | 생활 동선 보호글 |
```

- `글번호`를 추가한다. 제목은 리라이팅으로 바뀌지만 글번호는 바뀌지 않는다. 이 열이 있으면 제목 매핑이 아예 필요 없다
- 글번호를 모르면 `-`로 둔다. 추측해서 채우지 않는다. 리뷰릴스는 `리뷰릴스-NNN`으로 쓴다
- `작성일`을 비우지 않는다. 발행 후 며칠차인지가 성과 판정의 축이다
- 화면에서 확인한 행을 전부 적는다. 상위 3~5행만 적고 넘어가지 않는다

## 3. 관측 품질 섹션 (신규 필수)

```md
## 관측 품질

| 항목 | 값 |
| --- | --- |
| 수집 레벨 | L3 |
| TOP20 확보 행수 | 12 |
| 수집 제약 | 원본 다운로드 응답 지연으로 화면 확인값만 기록 |
```

- `TOP20 확보 행수`는 실제로 표에 적은 데이터 행 수다. 20을 목표로 하되 화면에서 본 만큼만 적는다
- 제약이 없으면 `수집 제약`에 `없음`이라고 쓴다. 비워두지 않는다
- 이 값이 5 미만인 날의 데이터로는 **어떤 글도 `faded`로 판정하지 않는다.** 성과 원장이 `unobserved`로 처리한다

관측이 부족한 것은 잘못이 아니다. 부족한 줄 모르고 판정하는 것이 잘못이다.

## 4. 실행 로그 섹션 (신규 필수)

```md
## 실행 로그

- 140번 본문 하단에 173번 내부 링크 삽입
- 139번 관련 글 섹션에 164번 추가
- 직원이 166번 URL 등록
```

- 그날 블로그에 **사람이 가한 변경**을 적는다. 내부 링크 삽입, 본문 수정, URL 등록, 리라이팅, 삭제
- 아무것도 안 했으면 `- 없음`이라고 쓴다. 섹션을 통째로 빼지 않는다
- 조회수 변화를 해석할 때 이 로그를 먼저 본다. 링크를 심은 날의 상승을 검색 성과로 읽지 않는다

## 5. 발행일 등록 의무

성과 판정의 기준선은 발행일이다. 발행일이 없으면 그 글은 영원히 `unobserved`다.

**URL을 등록하는 순간 발행일도 같이 등록한다.** 등록 위치는 `POSTING_REGISTRY.json`의 `발행 상태 관리` 표(`#`, `파일`, `발행상태`, `발행일`, `URL`)다. 이 표가 발행일의 단일 권위 소스다.

- 발행일은 네이버 통계 `게시글 조회수 TOP 20`의 `작성일`을 최우선 기준으로 한다
- TOP20에 아직 안 뜬 글은 직원이 실제 포스팅한 날짜로 적는다
- 모르면 비워두고 `발행일 미상`으로 남긴다. 추측해서 채우지 않는다

### 미해결 항목

2026-07-27 기준으로 163~173번 11편은 발행일이 등록되어 있지 않다. daily TOP20에도 한 번도 등장하지 않아 저장소 데이터로는 확정할 수 없다. **사장님 또는 직원이 네이버에서 확인해 채워야 한다.**

## 6. 검사 기준

`scripts/validate_daily_report.js`가 2026-07-28 이후 daily에 대해 아래를 FAIL로 처리한다.

| 항목 | 기준 |
| --- | --- |
| `## 관측 품질` 섹션 | 존재. `TOP20 확보 행수`와 `수집 제약` 항목 포함 |
| `## 실행 로그` 섹션 | 존재. 최소 1개 항목 (없으면 `- 없음`) |
| TOP20 표 헤더 | `글번호`와 `작성일` 열 포함 |

`scripts/validate_data_schema.js`가 아래를 WARN으로 처리한다.

| 항목 | 기준 |
| --- | --- |
| 발행일 누락 | 등록부에 URL이 있는데 `발행 상태 관리` 표에 발행일이 없는 글 |

발행일 누락을 FAIL이 아니라 WARN으로 두는 이유는, 163~173번 11편이 이미 그 상태이고 사람이 채워야 하기 때문이다. 11편이 해소되면 FAIL로 올린다.

컷오버 날짜는 `config/post_validation_policy.json`의 `daily_contract_v2_from`으로 관리한다.

## 7. 하지 않는 것

- 과거 daily를 새 형식으로 고쳐 쓰지 않는다. 기록은 증거다. 파서가 형식에 맞춘다
- 관측이 부족한 날을 추정값으로 메우지 않는다
- 실행 로그에 계획을 적지 않는다. 실제로 한 것만 적는다
- 공감·댓글 수를 관측 품질 지표로 쓰지 않는다
