# 문장군 브릿지 글감 운영 절차

> 목적: 문장군 제품 키워드 밖의 생활·공정·가구·주거 검색에서 실제 문·중문 의사결정으로 이어지는 질문을 찾되, 종합 인테리어 업체처럼 영역을 넓히거나 기존 글을 반복하지 않는다.

## 1. 브릿지의 정의

브릿지 글은 큰 키워드 뒤에 `문`이나 `중문`을 붙인 글이 아니다. 부모 키워드를 검색한 사람이 실제로 문 때문에 공정 순서, 마감 경계, 반입 동선, 원인 분리, 일정, 예산, 계약 또는 생활 불편에서 막힐 때만 성립한다.

```text
부모 키워드
→ 고객이 부모 영역에서 하려는 일
→ 문·중문 때문에 생기는 실제 결정
→ 문장군이 취급하는 서비스 범위
```

예시:

```text
입주청소
→ 입주 전에 집 전체 청소 일정을 잡음
→ 중문 설치를 나중에 하면 분진 때문에 다시 청소할지 걱정됨
→ 중문 설치와 청소의 선후관계를 설명
```

## 2. 제품 레인과 분리

| 구분 | 제품 레인 | 브릿지 레인 |
| --- | --- | --- |
| 출발점 | 중문·방문·ABS도어 키워드 | 생활·공정·가구·주거 부모 키워드 |
| 수집 | `npm run keywords:product` | `npm run keywords:bridge` |
| 검사 | `npm run topic:check` | `npm run topic:bridge-check` |
| 범위 | 문장군 제품 안쪽 | 부모 검색 의도와 문 서비스의 실제 연결 |
| 데이터 | `keyword_data_product*` | `keyword_data_bridge*` |

기존 `config/product_scope.json`의 `out_of_domain`을 브릿지 때문에 삭제하지 않는다. 제품 레인은 계속 종합 인테리어 소재를 차단한다. 브릿지 레인은 부모와 서비스를 분리 입력해, 서비스만 기존 제품 범위로 검사한다.

## 3. 부모 키워드 수집

기본 시드 뱅크 전체를 조회한다.

```powershell
npm run keywords:bridge
```

새 부모 키워드만 시험할 때는 설정을 고치지 않는다.

```powershell
npm run keywords:bridge -- --seeds "로봇청소기,유모차,붙박이장"
```

`config/bridge_seed_keywords.json`은 허용 목록이 아니다. 반복 수집할 기본 시드를 보관할 뿐이며, 새로운 부모 키워드는 CLI로 바로 조회할 수 있다.

수집 파일:

- `data/raw/keyword_data_bridge.json`
- `data/raw/keyword_data_bridge.meta.json`
- `data/raw/keyword_data_bridge.md`

이 파일은 기존 제품 키워드 데이터를 덮어쓰지 않는다.

## 4. 후보 구조화

후보는 아래 다섯 값을 먼저 쓴다.

```text
parent_keyword: 부모 검색어
service_keyword: 문장군 실제 서비스
relation_type: 연결 관계
customer_question: 고객이 실제로 할 질문
dependency_statement: 문 때문에 실제로 막히는 이유
```

지원 관계:

- `sequencing`: 공정 순서
- `finish_interface`: 마감 경계
- `clearance_logistics`: 반입 폭과 동선
- `cause_diagnosis`: 원인 분리
- `schedule`: 일정 역산
- `budget_priority`: 예산 우선순위
- `contract_responsibility`: 계약과 책임
- `lifestyle_friction`: 생활 불편

## 5. 후보 검사

```powershell
npm run topic:bridge-check -- `
  --parent "입주청소" `
  --service "중문설치" `
  --relation "sequencing" `
  --question "입주청소를 먼저 하면 중문 설치 후 다시 청소해야 하나?" `
  --dependency "중문 설치의 분진과 작업 동선 때문에 청소와 문 시공 순서를 함께 정해야 한다."
```

자동 BLOCK:

- 부모 키워드가 영구 제외 또는 미취급 제품을 우회함
- 문장군 서비스가 기존 제품 범위에서 BLOCK
- 등록되지 않은 연결 관계
- 고객 질문 또는 의존 문장 누락
- 의존 문장에 구체적인 문 서비스 연결이 없음
- 같은 고객 질문이 등록부에 이미 존재함

WARN은 자동 승인 의미가 아니다. 부모·서비스·질문 근접 글의 제목과 소재를 직접 읽는다.

## 6. 사람 판정

아래 질문에 모두 답해야 scorecard 후보로 올린다.

1. 부모 검색자가 실제로 문 때문에 결정에 막히는가
2. 부모 업종의 일반 정보가 아니라 문 시공과 맞물리는 지점이 주제인가
3. 기존 작성완료·URL등록대기 글을 포함해 같은 질문이 없는가
4. 문장군이 청소·타일·도배·가구·창호 서비스를 제공하는 것처럼 읽히지 않는가
5. 부모 검색량 전체가 브릿지 질문으로 넘어온다고 과장하지 않았는가
6. 실제 현장 사진 또는 상담 장면으로 후매칭 가능한가
7. 법률·성능·하자 책임 주장은 최신 직접 근거를 확보했는가

## 7. 기존 글 보호

부모 키워드가 새로워도 같은 질문이면 신규 글이 아니다.

- 도배·방문교체 순서: 165 보호
- 이사 전후 중문 설치 시점: 116 보호
- 소파·침대 등 큰 가구 반입과 중문: 136 보호
- 화장실 타일 경계와 문 교체: 007·026·053·103 보호
- 신발장 간섭: 025·039 및 관련 글 보호
- 셀프중문 설치선: 200 보호

기존 글이 같은 질문에 답한다면 기존 URL 보강·내부링크·제목 실험 대상으로 돌리고 새 번호를 만들지 않는다.

## 8. 201~207 운영

201~207은 브릿지 후보 전체를 수집·검사한 뒤 별도 코호트로 정한다. 180~191 리라이팅 코호트의 모수와 8월 31일 판정 기준은 바꾸지 않는다.

후보 선정과 원고 작성 전에 `docs/strategy/BRIDGE_COHORT_PREREGISTRATION_20260824.md`를 적용한다. 7건은 확정 실험이 아니라 탐색 코호트이며, 부모 의도 7개·서비스군 최소 3개·서비스군당 최대 2건 조건을 충족한 승인표를 먼저 고정한다. 첫 발행 뒤 결과에 따라 후보를 교체하거나 분모를 줄이지 않는다.

브릿지 원고를 작성완료하면 URL 유무와 관계없이 즉시 `POSTING_REGISTRY.json`에 등록해 다음 후보의 중복 방지 대상이 되게 한다. 발행 전에는 일반 원고와 동일하게 `validate:posts`와 `gate:blog`를 통과해야 한다.
